### Proposal 1: Hysteresis Deadband for Threshold Controls

**What**: Replace binary threshold `u = 1 if x > theta else 0` with hysteresis:
```python
# For each threshold-based control ui with threshold thetai:
if x > thetai + delta:  # delta = 0.1 * thetai or param
    ui = 1
elif x < thetai - delta:
    ui = 0
else:
    ui = ui_prev  # maintain previous state
```

**Why**: Prevents chattering when state oscillates near threshold; physical systems have inherent hysteresis (neural firing thresholds, biochemical activation); matches control theory best practice for bang-bang systems.

**Avoids failure pattern**: "Threshold-Switching Instability" — hysteresis explicitly breaks the zero-deadband condition causing infinite switching.

**Expected impact**: Reduce u3/u6 switches from ~30,000 to <100; eliminate min-interval=0s violations; state deviations may increase slightly (slower response) but total cost dominated by chattering reduction.

**Risk & mitigation**: 
- Risk: Increased state deviation if delta too large → make delta state-dependent or parameter-tunable
- Risk: Memory overhead for ui_prev → store as scalar in state or params dict

### Proposal 2: Minimum Dwell-Time Enforcement

**What**: Add explicit minimum on-time/off-time constraints:
```python
# Track time since last switch in state or params
if proposed_switch and (t - last_switch_time[ui_idx] > tau_min):
    execute_switch
    last_switch_time[ui_idx] = t
else:
    maintain_current_state
```

**Why**: Directly addresses the 0.000s min-interval violations; enforces physical realizability (neural/population dynamics have refractory periods); independent of hysteresis, can be combined.

**Avoids failure pattern**: "Threshold-Switching Instability" — minimum dwell time is a stronger constraint than hysteresis, guaranteeing finite switching rate.

**Expected impact**: Guaranteed elimination of rapid switching; tau_min = 0.05s would limit switches to <60 per control; cost impact similar to Proposal 1 but more predictable.

**Risk & mitigation**:
- Risk: Artificial constraint may prevent necessary rapid response → make tau_min control-specific (smaller for u1/u2, larger for u3/u6)
- Risk: Implementation complexity → use simple counter or time-tracker in params
